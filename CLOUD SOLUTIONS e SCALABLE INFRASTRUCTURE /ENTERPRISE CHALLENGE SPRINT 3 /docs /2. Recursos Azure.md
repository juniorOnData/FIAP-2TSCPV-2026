# Azure Infrastructure

## Visão geral

A infraestrutura do projeto está hospedada na Microsoft Azure e foi organizada para separar computação, persistência, armazenamento, rede e observabilidade.

A maior parte dos recursos está provisionada na região **Chile Central**, dentro do Resource Group `rg-nexusops-locaweb`. O Azure Container Registry está localizado em **Norway East**, utilizado para o processo de build da imagem da aplicação.

A aplicação é executada em um Azure Container Instance, utiliza Azure Database for MySQL para persistência e Azure Blob Storage para armazenamento de arquivos. O monitoramento é realizado por meio do Log Analytics, Application Insights e Azure Monitor.

## Arquitetura

A infraestrutura pode ser representada de forma simplificada da seguinte maneira:

```text
                         Internet
                            │
                            ▼
                 ┌─────────────────────┐
                 │ Azure Container      │
                 │ Instance             │
                 │                      │
                 │ FastAPI :8000        │
                 └──────────┬──────────┘
                            │
              ┌─────────────┼─────────────┐
              │             │             │
              ▼             ▼             ▼
        ┌──────────┐  ┌───────────┐  ┌─────────────┐
        │  MySQL   │  │   Blob    │  │ Application │
        │ Database │  │  Storage  │  │  Insights   │
        └──────────┘  └───────────┘  └─────────────┘
              │                             │
              └──────────────┬──────────────┘
                             ▼
                     Azure Monitor
                     Log Analytics
```

A aplicação fica dentro da infraestrutura de rede definida pela VNet `vnet-nexusops`, enquanto o banco de dados é separado em uma subnet específica para os recursos de dados.

## Resource Group

O Resource Group utilizado pela solução é:

```text
rg-nexusops-locaweb
```

A região principal é **Chile Central**. A região **Norway East** é utilizada pelo Azure Container Registry para o processo de build da imagem.

## Containerização

### Azure Container Registry

O Azure Container Registry armazena a imagem Docker utilizada pela aplicação.

```text
Nome: acrnexusops8929
Região: Norway East
SKU: Standard
Admin: Enabled
Login Server: acrnexusops8929.azurecr.io
```

A imagem atualmente utilizada é:

```text
acrnexusops8929.azurecr.io/nexusops-api:latest
```

O processo de publicação segue o fluxo:

```text
Dockerfile
    │
    ▼
Azure Container Registry
    │
    ▼
Azure Container Instance
```

### Build e publicação

O login no registry pode ser realizado com:

```bash
az acr login --name acrnexusops8929
```

O build e o envio da imagem podem ser executados diretamente pela Azure:

```bash
az acr build \
  --registry acrnexusops8929 \
  --image nexusops-api:latest \
  --file docker/Dockerfile .
```

Para consultar as imagens disponíveis:

```bash
az acr repository list --name acrnexusops8929
```

A imagem documentada possui aproximadamente 400 MB.

Os valores apresentados como placeholders representam secrets que devem ser fornecidos pelo ambiente de execução.

O FQDN utilizado pela aplicação é:

```text
mysql-nexusops-8929.mysql.database.azure.com
```

O database utilizado é `db_nexusops`, com `utf8mb4` e collation `utf8mb4_unicode_ci`.

### Estrutura do banco

A tabela `tb_previsoes` armazena os resultados gerados pela aplicação:

```sql
CREATE TABLE tb_previsoes (
    id INT PRIMARY KEY AUTO_INCREMENT,
    data_previsao DATETIME NOT NULL,
    d_plus_1 FLOAT NOT NULL,
    d_plus_7 FLOAT NOT NULL,
    registros_ingeridos INT NOT NULL,
    criado_em TIMESTAMP DEFAULT CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

Os registros de auditoria são armazenados em `tb_auditoria`:

```sql
CREATE TABLE tb_auditoria (
    id INT PRIMARY KEY AUTO_INCREMENT,
    operacao VARCHAR(50) NOT NULL,
    qtd_registros INT NOT NULL,
    status VARCHAR(20) NOT NULL,
    mensagem TEXT,
    criado_em TIMESTAMP DEFAULT CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

### Firewall e backup

O acesso ao banco é configurado para permitir a conexão da aplicação. A regra documentada utiliza o IP da ACI como origem.

O ambiente possui retenção de backup de 7 dias, configuração geo redundante e possibilidade de point in time restore dentro do período configurado.

Para realizar uma conexão pelo Cloud Shell:

```bash
mysql \
  -h mysql-nexusops-8929.mysql.database.azure.com \
  -u azureuser@mysql-nexusops-8929 \
  -p
```

## Armazenamento

### Azure Blob Storage

O Storage Account utilizado pela aplicação é:

```text
Nome: stnexusops8929
Região: Chile Central
Kind: StorageV2
Tier: Hot
Replication: GRS
HTTPS Only: Yes
```

Os containers estão organizados de acordo com sua finalidade:

```text
raw/
    Arquivos CSV de entrada

processed/
    Dados processados

logs/
    Logs da aplicação

backups/
    Backups do banco, quando utilizados
```

A configuração utiliza armazenamento geo redundante, proporcionando uma camada adicional de proteção para os dados armazenados.

### Operações

Para listar os containers:

```bash
az storage container list \
  --account-name stnexusops8929
```

Para enviar um arquivo:

```bash
az storage blob upload \
  --account-name stnexusops8929 \
  --container-name raw \
  --name incidentes.csv \
  --file data/sample_incidentes.csv
```

Para baixar um arquivo processado:

```bash
az storage blob download \
  --account-name stnexusops8929 \
  --container-name processed \
  --name resultado.csv \
  --file resultado.csv
```

## Rede

### Virtual Network

A infraestrutura de rede utiliza a VNet:

```text
Nome: vnet-nexusops
Address Space: 10.0.0.0/16
Região: Chile Central
```

A rede é dividida em duas subnets:

| Subnet        | CIDR          | Finalidade     |
| ------------- | ------------- | -------------- |
| `subnet-app`  | `10.0.1.0/24` | Aplicação      |
| `subnet-data` | `10.0.2.0/24` | Banco de dados |

A `subnet-app` concentra a aplicação executada pelo ACI. A `subnet-data` é destinada aos recursos de dados e permite tráfego MySQL originado da rede da aplicação.

### Regras de tráfego

As regras documentadas são:

| Subnet | Ação  | Porta | Origem        | Protocolo |
| ------ | ----- | ----- | ------------- | --------- |
| `app`  | Allow | 8000  | `*`           | HTTP      |
| `app`  | Allow | 443   | `*`           | HTTPS     |
| `data` | Allow | 3306  | `10.0.1.0/24` | MySQL     |

A regra da subnet de dados restringe o tráfego MySQL à rede utilizada pela aplicação.

## Observabilidade

A infraestrutura utiliza três componentes principais para monitoramento: Log Analytics, Application Insights e Azure Monitor.

### Log Analytics

O workspace utilizado é:

```text
Nome: law-nexusops
Região: Chile Central
Retention: 30 dias
SKU: Pay As You Go
```

Entre as tabelas utilizadas estão:

```text
AzureMetrics
AzureDiagnostics
ContainerInstanceLog_CL
AppServiceHTTPLogs_CL
```

Essas fontes permitem centralizar métricas, eventos e logs relacionados à infraestrutura e à aplicação.

### Application Insights

O Application Insights utilizado pela aplicação é:

```text
Nome: appi-nexusops
Região: Chile Central
Workspace: law-nexusops
```

A instrumentação é realizada na aplicação Python por meio do Azure Log Handler:

```python
from opencensus.ext.azure.log_exporter import AzureLogHandler
import logging

instrumentation_key = os.getenv("APPINSIGHTS_INSTRUMENTATIONKEY")

logging.getLogger().addHandler(
    AzureLogHandler(
        connection_string=f"InstrumentationKey={instrumentation_key}"
    )
)
```

As métricas acompanhadas incluem requisições HTTP, latência, exceções, performance da aplicação e eventos personalizados.

### Azure Monitor

Os alertas configurados estão relacionados principalmente ao consumo de recursos e à disponibilidade da aplicação.

| Alerta        | Métrica      | Condição      | Ação          |
| ------------- | ------------ | ------------- | ------------- |
| CPU alta      | CPU          | > 80%         | Email e SMS   |
| Memória alta  | Memory       | > 85%         | Email         |
| Error Rate    | HTTP 5xx     | > 5 erros/min | Email e Log   |
| DB Connection | MySQL Status | Down          | Email urgente |

O dashboard `nexusops-monitoring` reúne informações de CPU, memória, requisições, erros, tempo de resposta, conexões do banco e eventos personalizados.

Para criar um alerta de CPU:

```bash
az monitor metrics alert create \
  --resource-group rg-nexusops-locaweb \
  --name alert-cpu-high \
  --description "ACI CPU > 80%" \
  --scopes /subscriptions/{id}/resourceGroups/rg-nexusops-locaweb/providers/Microsoft.ContainerInstance/containerGroups/aci-nexusops-api \
  --condition "avg Percentage CPU > 80" \
  --window-size 5m \
  --evaluation-frequency 1m
```

Para consultar as métricas disponíveis:

```bash
az monitor metrics list-definitions \
  --resource /subscriptions/{id}/resourceGroups/rg-nexusops-locaweb/providers/Microsoft.ContainerInstance/containerGroups/aci-nexusops-api
```
